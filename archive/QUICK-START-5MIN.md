# QUICK-START-5MIN.md - 5分钟快速参考卡

**给：** 新 AI、新人、或任何需要快速上手的人

**用途：** 5 分钟内了解规范体系，准备好开始工作

---

## ⚡ 2 分钟：核心概念

### 四大编码原则

```
1️⃣ Think Before Coding
   问清楚：需求是什么、假设是什么、有多确定

2️⃣ Simplicity First
   只做需要的，不做预期中的

3️⃣ Surgical Changes
   只改必需部分，保持整体风格

4️⃣ Goal-Driven Execution
   清晰的成功标准，每一步都能验证
```

### 三种改动方式

```
你的改动符合以下哪一种？

🟢 简单改动（<50行，单文件，不改接口）
   工作流：Understand → Implement → Done
   时间：15分钟
   权限：完全自主

🟡 常规改动（50-500行，或新增功能，或新依赖）
   工作流：Understand → Design → ✋确认 → Implement → Review → Done
   时间：2-4小时
   权限：自主分析，设计需确认，之后自主到底

🔴 复杂改造（>500行，或跨系统，或高风险）
   工作流：Research → Design → ✋确认 → 分阶段Implement → Review → Done
   时间：1-5天
   权限：自主分析，关键决策需确认，分阶段执行
```

## ⚡ 2 分钟：工作流检查清单

### 🟢 简单改动

```
[ ] 明确改动原因
[ ] 实现改动（遵循四大原则）
[ ] 运行快测
[ ] 更新 docs/progress.md
[ ] 完成
```

### 🟡 常规改动

```
【理解需求】
[ ] 确认假设
[ ] 列出权衡（至少 2 种方案）
[ ] 确认边界

【设计方案】
[ ] 分析不同做法
[ ] 如涉及技术决策，查证 GitHub 参考
[ ] 制定清晰方案

【等待确认】
[ ] 展示方案给用户
[ ] 等待用户确认

【实现】(确认后完全自主)
[ ] 派发实现任务
[ ] 编写代码（遵循四大原则）
[ ] 运行快测

【审查】
[ ] 代码审查（检查 scope 漂移）
[ ] 完整门禁通过

【完成】
[ ] 合并到 main
[ ] 更新 docs/progress.md
[ ] 记录决策到 docs/decisions.md
```

### 🔴 复杂改造

```
【深度理解】
[ ] 彻底理解现有系统
[ ] 列出权衡和风险

【深度调研】
[ ] 查证 3-5 个相关项目
[ ] 深度对比分析

【完整设计】
[ ] 制定详细设计文档
[ ] 完整技术方案
[ ] 风险评估

【内部审查】
[ ] 由独立 Agent 审查
[ ] 检查设计缺陷

【等待确认】
[ ] 展示给用户
[ ] 等待确认

【分阶段实现】(确认后)
对每个阶段：
  [ ] 实现
  [ ] 中间测试
  [ ] 中间审查
  [ ] 修复 bug（如有）
  [ ] 进行下一阶段

【最终】
[ ] 整体审查
[ ] 集成测试
[ ] 合并

【完成】
[ ] 更新所有文档
[ ] 记录完整决策
```

## 常见问题

**Q: 不确定是简单还是常规怎么办？**
A: 倾向保守，选常规。常规的工作流更安全。

**Q: 为什么需要查证 GitHub？**
A: 避免重复造轮子，参考成熟实现能减少 bug 和设计缺陷。

**Q: 改动完后一定要更新文档吗？**
A: 是的。后面接手的 AI 需要知道你的决策理由。

**Q: Skill 是什么？**
A: 自动化工具集合。不同的改动类型需要不同的 skill。
   - oil-explore：理解代码
   - oil-plan：制定方案
   - oil-code-review：审查代码
   - 等等

**Q: 用户说"这是L1"但看起来像常规怎么办？**
A: 确认一下："我理解您说这是简单改动，确认一下条件..."
   如果确实不符合，报告给用户，等待用户确认。
