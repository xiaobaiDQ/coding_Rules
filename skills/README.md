# skills/README.md - 使用 Agent Skill（可选）

**本库不绑定任何 Skill 实现。** 不装 Skill，整套规范照样完整可用。
这一页只讲"什么时候值得用、接入时要注意什么"，不指定具体产品。

具体实现五花八门（各家 Agent 宿主都有自己的 Skill 生态）。本库只把
**我当前在用的一套**作为可选示例放在 [OIL-DEV-SKILLS.md](OIL-DEV-SKILLS.md)，
换掉它不影响任何规范。

---

## 一、Skill 解决什么问题

把一次改动拆成可分工、可检查的几步，避免"一个 AI 从头写到尾、自己夸自己"。

按职责看，通常需要这几类能力（叫什么名字不重要）：

| 职责 | 该做什么 | 什么时候不需要 |
|---|---|---|
| 探索 | 只读摸清代码、调用链、可复用组件 | 你已经知道改哪个文件 |
| 方案 | 写人能看懂的方案、列取舍、定验收 | 单文件小修 |
| 实现 | 按契约改代码、只跑快测 | 改动只有几行 |
| 审查 | 对照方案和项目约定检查已写的代码 | 同上 |
| 缺陷 | 先复现、找根因、在源头修 | 原因已明确的笔误 |
| 治理 | 文档、测试分层、分支与工作树盘点 | 项目还很小 |

判断标准不是"有没有装工具"，而是：**这次改动值不值得多一道独立检查。**

## 二、接入任何 Skill 都要满足的要求

1. **项目约定写在 `AGENTS.md`**，包括快测、门禁、高危目录、禁改目录。
   Skill 自己不应该要求你另建一套配置文件。
2. **命令必须是你跑通过的。** 从 README 抄来没跑过的命令，会让 AI 一路"验证通过"的假象。
3. **高危目录先划出来**（认证、支付、迁移、发布、密钥），Skill 才知道哪里要停。
4. **合并主干、发布、改数据结构、删数据，永远人工确认**，不交给 Skill 自动完成。
5. **默认只读起步。** 第一次在某个仓库用，先让它探索和出方案，不要直接赋予写权限。
6. **清楚代码外发与成本。** 私有代码会进入外部模型；多 Agent 会成倍消耗 token。

## 三、要不要写项目专有 Skill

先回答四个问题，有一个"否"就先别写：

1. 会被反复调用吗（不是一次性任务）？
2. 有稳定的输入输出，能独立验证吗？
3. 包含项目特有知识（领域规则、内部系统、特殊流程）吗？
4. 有明确触发场景，且不和已有 Skill 抢活吗？

用事实判断，不用打分模型：

- 能否独立调用、独立维护
- 权限和副作用是否与别的 Skill 明显不同
- 是否有稳定的触发描述
- 是否真的减少了重复劳动

优先**补充**已有 Skill，而不是替换：替换会让上游更新失效，还得自己长期维护。

---

## 四、边界

- Skill 是**辅助流程**，不能替代项目的架构评审、安全评审和合规要求。
- 不同宿主的 Skill 格式不通用，换工具时要重写触发描述，不要假设可以照搬。
- 本库不打包、不安装、不更新任何 Skill；版本和用法以各自官方文档为准。
- 不要把第三方 Skill 的文档抄进本库，只留入口。
