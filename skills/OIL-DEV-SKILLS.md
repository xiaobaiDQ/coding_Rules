# OIL-DEV-SKILLS.md - 可选实现示例

> **这是示例，不是规范要求。** 我目前用这一套跑开发流程；不用它、换别的工具，
> 本库其余部分完全不受影响。用法以官方仓库为准：
> <https://github.com/oil-oil/oil-dev-skills>

---

## 它是什么

六个可独立使用的 Agent Skill，把一次改动拆成：
摸清代码 → 写方案 → 委托实现 → 独立审查 → 收尾治理；
另有一条"先复现、找根因再修"的缺陷支线。

| Skill | 用途 |
|---|---|
| `oil-explore` | 只读摸清代码、调用链、可复用组件 |
| `oil-plan` | 按复杂度分级写方案、内审、派发契约、验收合并 |
| `oil-delegate` | 按契约把实现交给子 Agent 或当前会话 |
| `oil-code-review` | 审查已写出的改动，对照方案与项目约定 |
| `oil-bug-fix` | 先复现、找根因、在源头修，再判断是否普遍问题 |
| `oil-govern` | 文档与 `AGENTS.md` 治理、测试分层、分支与工作树盘点 |

小改动不用走完整流程：说清改法，直接改，跑相关快测。

## 安装与前置

1. 按官方 README 的安装说明操作（支持 Claude Code、Codex 等宿主）。
2. 需要 **Python 3.10+**。`<python>` 在 macOS/Linux 通常是 `python3`，Windows 通常是 `py -3`。
3. 官方声明：脚本目前**只在 macOS 实机验证过**，Linux 与 Windows 尚未验证。
   在非 macOS 环境使用前，先单独跑一遍它自带的脚本确认可用。

本库不提供安装脚本，也不打包这些 Skill。

## 它读什么配置

读项目 `AGENTS.md` 里标题含 `oil-dev` 的小节（Dev Profile），键名大致是：

```yaml
quick-test:   <与改动相关的快测>
merge-gate:   <合并前完整验证>
high-risk:    <高风险目录>
do-not-edit:  <禁改目录>
```

本库模板里的"验证与边界"一节用的是同一批概念，只是键名更通用。
两处冲突时，**以模板的通用键为准**，再把它们映射到 `oil-dev` 小节。

它**不读** `PROJECT-ADAPT.yaml` 之类的文件。本库也不定义这类协议。

---

## 使用边界

- 合进主干、改数据库结构、发布、改对外接口：官方流程要求独立只读检查后由用户确认。
  不要把它配成自动合并。
- 子 Agent 会显著增加 token 消耗：给它用轻量模型，主会话只做决策和验收。
- 代码会进入外部模型，接入前确认公司政策与数据合规。
- 外部 Agent 默认只读；要它写代码时，先确认工作区干净、分支正确。

---

## 什么时候换掉它

- 官方脚本在你的平台不可用，或长期不维护
- 你的宿主不支持这类 Skill
- 团队已有一套更合适的流程

换掉时只需要：保留 `AGENTS.md` 里的命令与边界，替换"按什么流程做"。
规范部分（`coding/`）不需要任何改动。
